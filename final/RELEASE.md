## Known limitations

1. **Per-skill live evaluation not yet run.** The 16-scenario behavioral suite covers
   representative skills across categories; 40+ skills have no dedicated evaluation scenario.
   All 88 pass the mechanical validator (VR-1–VR-9), but live-agent behavioral verification
   at the per-skill level requires tooling not yet built. Skill status remains
   `authored, not yet validated/evaluated` until that gate is built and run.

2. **No VS Code extension adapter.** VS Code is listed as a target consumer in the
   project goals but no dedicated adapter was implemented. The `codex/` adapter covers
   GitHub Copilot (which runs in VS Code), but a native VS Code extension adapter with its
   own discovery mechanism is absent.

3. **rendering-strategy description length CE-1 warning.** `SK-FE-005` description is
   537 characters against the 500-character soft target. The CE-1 rule is advisory;
   the description is technically correct and does not fail VR-1.

4. **research/ not shipped.** The `research/` directory contains background research and
   technology notes used during skill authoring. It is not part of the consumable skill
   library and is not included in the `final/` package — only `skills/`, `core/`,
   `adapters/`, and the evaluation/audit records ship.

5. **Skill version granularity.** All skills are at `skill_version: "0.1.0"`. Per-skill
   versioning relative to the library version is not yet mechanically enforced — a future
   change to one skill does not yet auto-increment its version independently of the library
   version. This is a known open decision deferred from the initial scaffold.
