# MySQL 8.4.0 breaking changes (Tier-2 detail)

All items below are version-sensitive to the **8.0 → 8.4 LTS transition**
specifically. Primary source:
[Source: https://dev.mysql.com/doc/relnotes/mysql/8.4/en/news-8-4-0.html]
("Changes in MySQL 8.4.0"), via `research/technologies/mysql.md` §13.

No equivalent official breaking-changes enumeration for the 8.4→9.7 or
9.7→26.x transitions was located in the underlying research — treat any
claim about those transitions as unverified until a "Changes in MySQL 9.x"
or "Changes in MySQL 26.7.0" page is separately researched (likely at
`https://dev.mysql.com/doc/relnotes/mysql/9.7/en/` and whatever relnotes
path Oracle uses for the 26.x line).

## Replication

- **Replication SQL syntax removed** (not merely deprecated): `START SLAVE`
  / `STOP SLAVE` / `SHOW SLAVE STATUS` / `CHANGE MASTER TO` / `RESET SLAVE`
  / `SHOW MASTER STATUS` are removed in favor of `START REPLICA` /
  `STOP REPLICA` / `SHOW REPLICA STATUS` / `CHANGE REPLICATION SOURCE TO` /
  `RESET REPLICA` / `SHOW BINARY LOG STATUS`. Applications issuing the old
  syntax will error, not just warn.
- **Group Replication:** special-case handling for members running 8.0.17
  or earlier is removed — all Group Replication members must be on a recent
  8.0 patch before upgrading to 8.4; the default consistency level for
  Group Replication changed to `BEFORE_ON_PRIMARY_FAILOVER`.

## Authentication and TLS

- **`mysql_native_password` disabled by default**; must be explicitly
  turned on if legacy clients need it.
- **`default_authentication_plugin` variable removed**, replaced by
  `authentication_policy`.
- **`authentication_fido` / `authentication_fido_client` plugins removed**,
  replaced by `authentication_webauthn`.
- **`--ssl`, `--skip-ssl`, `--admin-ssl` options and `have_ssl` /
  `have_openssl` variables removed**, replaced by `--tls-version` /
  `--admin-tls-version`.

## Data types and schema

- **`AUTO_INCREMENT` on `FLOAT`/`DOUBLE` columns removed** as an error
  condition (was deprecated in 8.0) — pre-upgrade schema changes are
  required, or the table cannot be upgraded.
- **Column index-prefix support in partitioning keys removed** — a
  previously-deprecated pattern (`PARTITION BY KEY(id, name(10))`) is now a
  hard error at `CREATE TABLE`/`ALTER TABLE` time.
- **Non-unique/partial-key foreign keys restricted by default** via
  `restrict_fk_on_non_standard_key` (default now restrictive).
- **`LOW_PRIORITY` with `LOCK TABLES` removed** (syntax error).

## Privileges

- **`SET_USER_ID` privilege removed**; `GRANT SET_USER_ID ...` is now a
  syntax error. Replacement: `SET_ANY_DEFINER` + `ALLOW_NONEXISTENT_DEFINER`.

## Keyring and key management

- **Keyring plugins removed** in favor of component equivalents:
  `keyring_file` → `component_keyring_file`,
  `keyring_encrypted_file` → `component_keyring_encrypted_file`,
  `keyring_oci` → `component_keyring_oci`.

## INFORMATION_SCHEMA

- **`INFORMATION_SCHEMA.TABLESPACES` table removed**; use
  `INNODB_TABLESPACES` / `INNODB_DATAFILES` instead.

## Utilities removed

- **`mysql_upgrade`** (deprecated since 8.0.16) — replaced by automatic
  server-driven upgrade.
- **`mysqlpump`** (plus its `lz4_decompress`/`zlib_decompress` helpers) —
  replaced by `mysqldump` or MySQL Shell dump utilities.
- **`mysql_ssl_rsa_setup`** — replaced by automatic SSL/RSA generation by
  the server.

## Upgrade-path restriction

- **Direct MySQL 5.7 → 8.4 in-place upgrade not supported** — must go
  through 8.0 first, consistent with the general "cannot skip an LTS
  series" rule
  [Source: https://dev.mysql.com/doc/refman/9.7/en/upgrade-paths.html].
